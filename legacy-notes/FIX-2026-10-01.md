# Replay/API-budget/position-sizing fix

## Why replay stopped at about 10:30

Breeze v2 was requested with UTC times (`03:45Z` to `10:30Z`), but the returned `datetime` values were treated as India time when the trailing `Z` was absent. The session filter therefore retained only values labelled about `09:15` to `10:30`, giving 16 common replay candles.

The parser now treats Breeze historical `datetime` as UTC and converts to India time only for filtering/display. Historical replay is capped at 15:15 India time, so a normal complete day has 73 five-minute timestamps from 09:15 through 15:15 inclusive.

## Why API usage grew so quickly

The previous `RunDayAsync` re-ran `EnsureSignalContractsAsync` on every replay step. Because the timestamp bug made each contract look incomplete, all 8 signal contracts could be fetched again repeatedly. Hedge preview/chart loading could add more calls.

The new flow is:

- Start day replay:
  - load NIFTY cash full day once if missing;
  - load 4 CE + 4 PE signal contracts full day once if missing;
  - save a successful day/contract marker in `trading.candle_day_loads`.
- Previous/Next:
  - strategy replay reads PostgreSQL;
  - no repeated download of the 8 signal contracts.
- Hedge contract:
  - first preview/need for a new hedge strike can make one full-day API call;
  - that strike is then cached in DB and marked loaded.

Expected first-load usage for a new historical date is normally 9 historical calls (1 NIFTY + 8 options), plus one customer/session resolution call once per API process.

## Lots and lot size

Both are configurable in the Angular header. Single-day replay, range backtest and live mode all receive them.

Every trade now stores/displays:

- Lots
- Lot size
- Quantity = Lots × Lot size

`trading.strategy_trades` is upgraded automatically with `lots` and `lot_size` columns at API startup.

## Useful database checks

```sql
SELECT
    session_date,
    load_key,
    candle_count,
    loaded_at
FROM trading.candle_day_loads
WHERE session_date = DATE '2026-09-29'
ORDER BY load_key;
```

After the first replay load you should see one NIFTY row and eight signal-contract rows, plus any hedge contracts that were previewed/needed.

```sql
SELECT
    session_date,
    strike,
    option_type,
    COUNT(*) AS candles,
    MIN(candle_time AT TIME ZONE 'Asia/Kolkata') AS first_india,
    MAX(candle_time AT TIME ZONE 'Asia/Kolkata') AS last_india
FROM trading.premium_candles_5m
WHERE session_date = DATE '2026-09-29'
  AND product_type = 'options'
GROUP BY session_date, strike, option_type
ORDER BY strike, option_type;
```

For liquid signal strikes the timestamps should normally cover approximately 09:15 through 15:15 India time.

The API budget counter is not reset by application restart. If it already shows 501, those previously counted calls remain visible for the day. To verify the fix, note the number after Start day replay and then click Next several times. It should not rise for the already-loaded signal contracts.
